# AI共創工作室

以專案為核心的繁體中文共創工作台。每個專案可放多個創作項目，透過對談、方向確認、候選微調、比較與明確採用，保留使用者的判斷和完整版本歷程。

**第五階段：受限互動視覺程式（保留前十一類功能）｜PHP 7.4 相容語法／SQLite／OpenAI Responses API 或本機 Ollama／HTTP 網頁安裝。** 一般使用不需 CLI、Node、npm、Composer 或 MySQL。沒有帳號與團隊權限，只能在 PHP 主機本機使用，不可公開部署、開放區網、反向代理或隧道。

## 目前範圍

創作類型依登錄與介面順序如下：

1. 標題名稱（`titles`）：已實作。
2. 短文（`short_text`）：已實作。
3. 長篇文章（`article`）：已實作。
4. 圖文（`illustrated`）：已實作完整段落、既有固定圖片與原生排列，可編輯及匯出含圖 HTML。
5. 表格（`table`）：已實作原生列、欄、儲存格編輯及 CSV／TSV 匯出。
6. 圖表（`chart`）：已實作流程圖文字來源與 SVG 預覽，另提供長條／折線／圓餅統計模式。
7. 心智圖（`mindmap`）：已實作主題起步、待選分支、勾選入圖與原生節點編輯。
8. 向量圖形（`vector`）：已實作六種原生幾何／文字物件、屬性與圖層編輯及 SVG／JSON／TXT 匯出。
9. 圖片創作（`image`）：已實作外部 PNG／JPEG 本機準備、明確上傳版本、私人圖片預覽／下載、文字中繼資料編輯及實際圖片討論／比較；尚無 AI 像素生成、修改或融合。
10. 海報設計（`poster`）：已實作三部分方向確認、標題／文字／固定圖片區塊、原生版型及含圖 HTML 匯出。
11. 網頁（`webpage`）：已實作三部分方向確認、原生響應式單頁、完整內容編輯及 HTML／JSON／TXT 匯出。
12. 互動視覺程式（`interactive`）：已實作受限幾何主程式、可選動畫／游標互動、明確選用參數、原生 Canvas 安全預覽及 p5.js 主程式匯出。

十二類均已啟用，但能力各有邊界：圖片限上傳與分析，圖文／海報是文字搭配既有圖片的原生排版，互動視覺是有界宣告式幾何程式，不是任意 p5.js／JavaScript 開發或 AI 產圖。圖片生成模型仍待決定，沒有 AI 像素生成、修改或融合。「共聊」不在本次範圍。

## 專案、模型與歷史

- 專案保存共同名稱、說明與進度；每個創作項目各自保存對話、主軸、版本、正式版、比較與定稿紀錄，版號獨立。
- 在系統設定管理 AI 成員稱呼、服務、模型與啟用狀態，建立專案時一次選定成員／模型，專案內各項目固定共用，不逐句換人。沒有啟用成員時可先建空專案，完成設定後須明確綁定一次；舊未綁定專案也採相同流程，不推測原用模型。
- 綁定後若中央清單的原成員遭刪除、停用，或服務、模型、本機網址與綁定不同，AI 操作會阻擋。須恢復原設定；要使用其他模型請另建專案，不暗中替換。
- 每次 AI 結果保存當時成員與模型來源；歷史快照不隨中央改名或設定變動而重標，未回報的實際模型不猜測。
- 只有標題名稱在明確採用正式版時，才以主要名稱同步更新創作項目名稱。其他類型不因採用而更名；任何類型都不會因此改寫專案名稱／說明。

## 共創流程

以下生成／像素修訂／融合流程不適用於圖片；圖片以明確上傳建立版本，AI 只提供分析與文字建議。

工作區先顯示目前正式版完整內容，下方依序為「01 對談」「02 主軸與方向」「03 候選」，另有版本微調工作區及比較紀錄。長內容可捲動閱讀，版本依主版分組展開，保留小版本、實際來源與融合來源。

1. 說明用途、對象、核心訊息或限制。AI 在同一次討論回覆判斷方向是否足夠，足夠就整理待確認主軸；不足才釐清必要資訊，不要求固定三輪，也不另呼叫一次模型只判斷就緒。
2. 閱讀主軸，明確按「確認方向並生成候選」才開始生成。可以繼續討論，不會因方向備妥而自動生成。標題名稱每次 3–5 組、短文 3 篇；長篇文章、表格、圖表、心智圖、向量圖形、網頁、圖文、海報與互動視覺程式每次各 1 份完整候選；心智圖只需可探索的主題，不要求先選唯一方向。
3. 可直接選候選或正式版繼續微調，不必先採用。AI 修改另存完整小版本；單純評價／釐清不建立假修訂，不覆寫來源或正式版。
4. 短文以「全文」一欄完整修訂。長篇文章先選來源版本，再明確勾選段落；AI 看見來源全文，但只回傳選取段落，伺服器逐位元組保留未選原文，合併保存完整文章快照。未選範圍不預設全選。
5. 手動編輯可另存新主版或小版。文章可在手動完整編輯區新增、移除或改名段落；這與 AI 選段修訂不同，AI 不得藉選段操作改變段落結構。新段落用新 ID，既有段落保留 ID。
6. 比較與融合是兩個獨立操作，都需選 2–5 個未封存版本。比較依各版自身的目標、修改意見與內容說明取捨，不以目前共同目標統一排名；明確按融合才另行呼叫 AI，保存一個新主版本候選及全部來源，不自動選勝者或取代正式版。
7. 使用者明確選正式版、項目定稿或專案結案。封存／還原不刪歷史；正式版不能封存。重新開啟仍保留過往定稿快照。只有具有效方向及正式版的項目可定稿；舊規劃項目不會因新能力啟用就自動完成，可先封存再結案。

表格、圖表、心智圖、向量圖形、網頁、圖文、海報與互動視覺程式沿用同一流程：候選微調、手動另存主／小版、比較、融合、引用與定稿都保存完整結構化作品，不把畫面預覽或文字摘要當成原件，也不自動升為正式版。

每版有單一「本版目標與修改意見」欄，最多 12,000 UTF-8 bytes；修訂與比較優先使用它。舊分欄僅相容呈現，不重寫歷史、不疊加重複標籤。AI 生成與修訂的目標整理取自同一次回覆，不額外推論。

AI 明確提供的單選問題可直接按答案，亦可自由輸入；舊紀錄不補造選項。答案綁定當時項目、脈絡、來源版本及文章選段／心智圖目標節點，過期選項不能送出。點答案不清除尚未送出的文字草稿。

## 表格與圖表

- 表格直接編輯欄名、資料列與每格文字，可新增／移除列欄。這不是試算表計算引擎，不執行公式；欄列有穩定 ID，每次另存完整結構。
- 圖表預設為流程圖：編輯受限 Mermaid 風格的節點／連線文字，即時顯示本程式產生的 SVG，另附完整節點與連線文字列表。支援由上而下／由左至右、方框／菱形／圓角框、有標籤的箭頭與循環；不使用完整 Mermaid 引擎。
- 長條、折線、圓餅為可選統計模式，來源須是已提供資料的 TSV。缺資料要先釐清，不以範例數字冒充真實統計；流程圖則不要求統計數字。切換模式保留原來源，不替你轉換或清除，格式不符時須自行修正。
- 已保存版本可匯出：表格 CSV／TSV，流程圖 MMD 文字來源／SVG，統計圖 TSV／SVG；圖表另可明確按鈕複製來源。匯出不呼叫 AI、不改版本。沒有自動連動外部工具，也未驗證「圖坊」匯入相容性。
- CSV／TSV 的可疑公式文字會加前置單引號，統計數值的負號仍保留為數值。原始結構、標題／說明、ID、歷史與未改寫文字以專案 JSON 為準；單件匯出不是完整備份。

詳細流程圖語法與示範方式見[使用指南](docs/USER-GUIDE.md)。固定腳本示範使用虛構資料，不解析你的真實流程或統計，也不是真實 AI。

## 心智圖：先探索，再自行決定入圖

1. 說出一個主題即可起步，不要求先決定用途、讀者或唯一主軸。確認方向後，AI 生成 1 份候選：圖中只有主題根節點，另列 2–12 個待選分支，全部預設未勾選。
2. 選候選「以此版繼續微調」，在工作區勾選想要的分支，按「將勾選分支加入草稿」。單純閱讀、點節點、勾選或設正式版都不會自動把建議入圖。也可自行填寫子節點。
3. 節點名稱與說明先按「套用節點修改至草稿」；可明確移動或合併節點，不必現在收斂。合併保留來源名稱與說明，轉移子節點及待選分支；可復原本次編輯器內最近 20 步草稿操作。
4. 所有這些操作只改頁面草稿，最後須另存完整主／小版本。未套用的欄位文字須先套用或放棄，不能被當成已保存內容；重新整理可能遺失草稿。
5. 要請 AI 再延伸，先選已保存版本，於對談區指定一個已入圖節點。AI 只更新該節點的待選子分支，已入圖節點與其他節點的待選建議保持原樣。結果另存完整小版本，不直接入圖、不覆寫來源或正式版；剛加入的草稿節點須先另存才可成為 AI 目標。
6. 已保存版本提供 SVG／JSON／TXT 匯出。SVG 只畫已入圖節點；單件 JSON 同時保留完整樹與待選建議；TXT 分開標明兩者。完整版本、引用與模型歷史仍須用專案 JSON 備份。

比較仍依每版自己的目標。明確融合才產生另一份主版本候選；已入圖節點只能來自選定來源中已有的節點，新的角度留在待選區，不趁融合自動採用。詳見[使用指南](docs/USER-GUIDE.md)。

## 向量圖形：可編輯物件與 SVG 匯出

1. 說明用途、要表達的內容與必要限制；方向足夠後先確認，再生成 1 份完整原生向量候選。使用專案原有的文字／結構化模型，不另接圖片服務，不把文字描述或點陣圖片當成向量作品。
2. 以候選或正式版繼續微調，選取矩形、橢圓、線段、多邊形、折線或文字物件，修改位置、尺寸／頂點、名稱、填色、外框、不透明度及文字。可調整畫布大小／背景、新增、複製、移除或前後移一層，保留穩定物件 ID。
3. 欄位須先明確「套用至草稿」，再用外層按鈕另存完整主／小版本。尚未套用的文字在同頁切換物件、讀取最新狀態或忙碌重畫時保留；不會被當成已保存作品。整頁重新整理或關閉仍會失去未另存草稿。可復原最近 20 步草稿操作，不改已保存歷史。
4. AI 修訂以完整已保存作品為來源，不讀未另存草稿。比較依各版本自己的目標；明確融合才產生新的完整主版候選，不自動採用。僅換名稱、ID 或摘要，不能冒充新融合圖形。
5. 已保存版本可匯出 SVG／JSON／TXT。SVG 保留獨立幾何與文字，不是內嵌點陣截圖；JSON／TXT 保存完整原生資料，完整共創歷史仍須專案 JSON。匯出不呼叫 AI、不自動傳送到外部工具。

目前沒有拖曳繪製、任意 SVG 匯入、path／貝茲曲線、圖片嵌入、外部字型、濾鏡、JavaScript 或 CSS。文字使用本機可用的通用字型，跨軟體呈現可能不同。使用者所稱「形坊」的目前名稱與匯入規格尚未驗證，不能保證其匯入或無損相容。操作與座標說明見[使用指南](docs/USER-GUIDE.md)。

## 網頁：先分別確認風格、內容與功能

1. 說明網頁的用途與材料。AI 在同次對談整理三部分待確認方向：視覺風格、內容結構、操作功能與限制。逐一閱讀並勾選後，才可按「確認方向並生成候選」。單純勾選不呼叫 AI、不保存作品；新方向會清除舊勾選，不能沿用過期確認。
2. 生成 1 份完整原生響應式單頁，不是網頁文字提案。固定主題為 paper（紙感淺色）、midnight（午夜深色）、meadow（草地綠色）；可組合 hero 主視覺、text 文字、cards 卡片、faq 問答與 cta 行動區。頁內導覽與按鈕只指向同一作品內存在的區塊，FAQ 使用原生展開／收合。
3. 從候選或正式版繼續微調，可完整編輯標題、主題、導覽、區塊文字及順序、卡片／問答。先按「套用網頁設定至草稿」或「套用內容區塊修改至草稿」，再另存完整主／小版；未套用欄位須先套用或明確放棄。可復原最近 20 步草稿操作。同頁切換區塊、忙碌重畫與讀取最新狀態保留欄位草稿；整頁重新整理／關閉不保留未另存內容。
4. AI 只讀已保存來源，不讀頁面草稿。比較、明確融合、固定引用、採用與定稿保留完整原生作品及模型來源，不覆寫舊版、不自動設為正式版。可明確引用同專案其他項目的特定版本作為材料，來源改版不會自動連動，也不能把尚未提供的圖片當成已讀取內容。
5. 已保存版本可匯出 HTML／JSON／TXT。HTML 是固定 CSS 版型、純文字安全跳脫、無 JavaScript／外部資源請求的獨立靜態檔，保留頁內導覽與可展開 FAQ；JSON 保留完整可編輯原生資料，TXT 是同一份原生 JSON 的純文字檔。尚無網頁 JSON／HTML 檔案匯入介面，完整共創歷史仍須專案 JSON。

所有輸入文字包含標記及網址都僅作純文字顯示。沒有任意 HTML／CSS／JavaScript、外部圖片／字型／連結、表單提交、登入、付款、API、後端資料服務或部署。HTML 匯出不等於已上線；工作室仍僅能在 PHP 主機本機使用；網頁功能本身未放寬主頁 CSP 或增加可執行程式的 iframe 端點，既有圖片功能只另加 img-src blob: 供私人預覽。詳見[使用指南](docs/USER-GUIDE.md)。

## 圖片：外部上傳與實際分析

1. 在正式頁建立「圖片創作」項目，選擇自己的靜態 PNG／JPEG。選檔只在瀏覽器準備，不上傳、不呼叫 AI，也不需要 Key。原檔限 12 MiB、寬高各 8192 像素、總像素 16,777,216；不接受 SVG、GIF、WebP 或 APNG。
2. 瀏覽器依圖片方向及選擇的 0／90／180／270 度順時針旋轉，保持比例、不放大，製作最長邊 2048、上限 4 MiB 的 PNG 副本。填圖片標題與「本版目標與修改意見」，檢查預覽後明確按「保存圖片為新大版本」，或選定未封存來源後保存為小修改。只追加新版本，不自動改正式版，不改原圖。
3. 伺服器再次檢查 PNG 結構、CRC、受限解壓與圖片雜湊，只接受 8-bit RGB／RGBA 非交錯 PNG，移除中繼資料並重新壓縮。副本不保存原檔名、EXIF／IPTC／XMP 或色彩描述檔。縮圖、解碼、方向處理及移除色彩描述檔可能改變顯示色彩；不是原始影像、印刷色彩或典藏忠實度的備份。
4. 已保存版本可編輯圖片標題、替代文字、來源註記與本版目標，先套用文字再另存主／小版；手動另存只能沿用所選來源的同一圖片資產，不能用 JSON 偷換圖片。要更換像素，須在外部工具處理後重新明確上傳。
5. 圖片 AI 分析需另在專案確認一次「固定模型接收圖片分析資料」。這份同意綁定目前專案模型，不立即呼叫 AI。之後主動按送出、整理方向或比較，直接使用既有固定模型，不再逐次彈窗。模型須支援視覺輸入與所需輸出格式；不支援就明確失敗，不暗中換模型、服務或用文字描述冒充看圖。
6. 圖片討論／整理方向可傳送選定來源及固定圖片引用的實際 PNG 位元組；比較只傳所選 2–5 版的像素，固定引用仍可有文字脈絡，但其像素不混入比較。每次最多 5 個不同資產、原始 PNG 合計 12 MiB，並保存所用項目／版本、資產 ID 與 SHA-256 來源。分析只增討論／比較，不生成或修改像素，不新增假圖片版、不自動採用。
7. 「確認圖片方向（不生成圖片）」只確認目標；圖片生成、AI 像素修改及融合仍未開放。圖片可依共用流程明確採用、封存／還原、固定引用及定稿，封存與舊定稿不刪除圖片。固定腳本示範沒有圖片上傳或真正看圖分析。

圖片以私有 SQLite BLOB 保存，沒有公開資產網址，也不接受外部圖片 URL 或伺服器路徑。預覽／下載經 owner、專案、項目與已保存版本核對的同源 POST／CSRF 讀取，再使用短暫 Blob URL。只有頂端正式版自動載入，其餘候選／歷史／引用／比較圖片須明確按「載入此圖片預覽」，不會開頁就讀全部圖片。單專案圖片資產限 100 張／64 MiB，同一 owner 限 400 張／256 MiB；封存不釋放容量，沒有自動清理歷史圖片。

專案 JSON 只保存圖片中繼資料、歷史與來源，不包含 PNG，不能當完整圖片備份。請另下載各版 PNG，並在程式停止寫入時離線備份整個私有資料夾及設定；離線備份可能含 Session／暫存 Key，須私密保管、不可分享。詳見[使用指南](docs/USER-GUIDE.md)與[安全邊界](docs/SECURITY.md)。

## 第四階段：圖文與海報原生排版

1. 建立「圖文」或「海報設計」項目，沿用專案固定文字／結構化模型。若要使用圖片，先在同專案的「圖片創作」保存外部圖片版本，再明確加入該固定版本引用。不自動找圖、補圖、換圖或接新圖片服務；沒有圖片時可做純文字排版，不放假圖片。
2. 圖文保存完整段落、段落標題與圖說，提供純文字、圖片在上／左／右的排列，以及 paper／night／meadow 三種固定主題。海報保存標題、文字、圖片區塊，提供靠左／置中／靠右、直式／方形／橫式，以及 paper／night／festival 主題。海報是可延展的原生版面，不保證固定印刷尺寸或單頁列印。
3. 海報在「02 主軸與方向」分別確認「視覺風格」「完整文字內容」「圖文排列」，三項勾齊並明確按生成才產生一份完整候選。新方向會使舊勾選失效；不是網頁的內容結構／操作功能確認，也不因勾選而自動呼叫 AI。
4. 選候選或正式版微調，可修改作品設定、完整區塊文字、固定圖片選擇、排列／對齊，並新增、移除、上移或下移區塊。先按「套用作品設定至草稿」／「套用區塊修改至草稿」，或明確放棄未套用欄位，再另存完整主／小版。未套用欄位可跨同頁區塊切換及重畫保留，但整頁重新整理／關閉不保留未另存草稿；本編輯器沒有復原按鈕。
5. AI 生成、修訂、比較與明確融合只收到完整文字、原生排版及圖片標題、替代文字、來源註記、尺寸等中繼資料，沒有圖片像素。要真正看圖分析，須回到圖片項目另行明確同意並操作。排版融合不是圖片像素融合；每版保存自己的目標與固定引用，來源及舊正式版不會自動覆寫。
6. 目前引用加上來源版本實際沿用的歷史圖片引用會保存在新快照；移除目前引用不會刪掉歷史圖片。同一引用 ID 若對應不同固定快照會阻擋編輯／推論／保存，不猜測選用哪一張。引用、私人資產與所有權會重新核對，缺漏或被改動時拒絕，不以較新圖片替代。
7. 已保存版本可「下載完整排版 HTML」：經私人介面讀取該版確切固定 PNG，核對格式、尺寸、長度與 SHA-256 後內嵌，固定 CSS、純文字跳脫、無 JavaScript／外部連線／表單。圖片原始位元組依每次區塊內嵌計算，合計最多 20 MiB；HTML 因 base64 與文字可更大。缺圖、驗證失敗或切換後過期即整筆停止，不下載缺圖成品。JSON 只含可編輯排版與引用 ID，TXT 只含文字，均不含 PNG 或完整來源歷史，不是專案備份。

只有頂端正式版自動載入其圖片；其他版須按「載入此排版圖片預覽」，草稿須按「載入編輯草稿圖片預覽」。這些本機私人讀取與 HTML 匯出不是把圖片送給模型。離線固定腳本未提供圖文／海報示範，不能以假結果驗收。詳見[使用指南](docs/USER-GUIDE.md)與[安全邊界](docs/SECURITY.md)。

## 第五階段：受限互動視覺程式

1. 先說要呈現的畫面。02 依序檢視並確認「畫面視覺」「動畫效果」「參數設定說明」「互動表現」四部分，畫面視覺必填；動畫與互動可明確為「無」，參數可為無或待建議，純靜態作品也成立。四個方向勾選只是確認已閱讀，不會選用控制參數、呼叫 AI 或自動保存；新方向會使舊勾選失效。
2. 明確生成 1 份完整候選，包含矩形、橢圓、直線圖層及可選的 orbit／wave／pulse／spin 動畫、pointer／hover 游標互動。使用既有固定文字／結構化模型，只產生受限資料，不接圖片服務，也不執行模型提供的 JavaScript。
3. 初次 AI 參數提案全部未勾選，未選用時仍採圖層原值。以該版繼續微調，自己勾選參數並按「套用參數修改」，才開放數值／滑桿控制；作品採用、方向確認與參數選用互不替代。可調整目前值、還原前次值或「亂數已選用參數」，未選參數不跟著改變。已選參數會覆蓋其控制屬性的圖層原值。
4. 可編輯畫布、完整圖層、順序及參數定義。欄位先套用至草稿或明確放棄，再另存完整主／小版；保存完整主程式、參數選用、目前值與前次值。最近 20 步草稿可復原，不改已保存歷史；同頁重畫保留未套用欄位，整頁重新整理／關閉不保留未另存草稿。
5. 預覽是本程式的原生 Canvas 2D，不是 p5.js 執行器。初始只畫靜態第一影格；動畫須按「開始／繼續動畫」，可暫停、回到第一影格，作品時間最多 60 秒／1800 影格。游標互動須另外勾選啟用，與動畫播放分開；離開或重畫工作區會停止舊預覽。只有頂端正式版與編輯器自動建立畫布，候選／歷史／引用／比較須明確載入，並共用一個額外預覽位置。
6. AI 沿用已保存來源，不讀未另存草稿；不得替你勾選、取消或轉換參數控制目標。已選參數只應依本次明確要求改值，並精確保存原值為前次值；未選參數的既有值保持。要讓 AI 移除已選控制項或其圖層，先自己取消選用、套用並另存。融合前若同一控制項的選用、目前／前次值、範圍或步進衝突，會在呼叫 AI 前拒絕，須先手動統一；仍可先比較，不會偷偷選一版的控制狀態。
7. 已保存版可匯出 p5.js 主程式、JSON／TXT。JS 由可信任的固定產生器輸出，使用 p5 的畫布與 drawingContext，需自行提供 p5.js 函式庫及執行頁面；本包不附函式庫、不自動載入 CDN、連網、上傳或部署。JSON／TXT 保存完整原生資料；沒有檔案匯入介面，完整歷史仍須專案 JSON。

最多 40 個圖層、24 個參數，畫布各邊最多 2048，完整作品最多 60,000 UTF-8 bytes。沒有任意程式編輯、eval、iframe、外部資源、圖片像素、文字繪圖、音訊或 WebGL；作品標題及圖層／參數名稱只作純文字說明。固定腳本示範明確不提供此類。尚未在真實瀏覽器、真正 p5.js runtime 或真實模型驗收，也不保證跨環境像素完全相同。詳細操作與官方 p5 參考連結見[使用指南](docs/USER-GUIDE.md)。

## 固定引用與容量

可明確引用同專案其他項目的某個未封存版本，保存完整內容與模型來源的固定快照。來源後來改版、封存或換正式版不會自動更換引用；需要新版時，移除舊引用再加入。AI 只能參考，不能修改被引用作品。

以下為 UTF-8 位元組，不是中文字數：

- 標題名稱：1–12 個自訂內容欄位，每欄 6,000、合計 24,000 bytes。
- 短文：固定 `body／全文` 一欄，最多 12,000 bytes。
- 長篇文章：1–80 段，每段 6,000、完整保存合計 120,000 bytes。單次 AI 生成／融合限 36,000 bytes；AI 選段修訂的來源段落合計限 24,000 bytes，回傳選段合計限 36,000 bytes，且不得超過全文扣除未選段落後的剩餘容量。超限拒絕，不悄悄截短或用摘要冒充全文。
- 表格：1–12 欄、1–100 列，每格 2,000、欄名 120、表格說明 600 bytes；完整作品 JSON 及文字投影各最多 60,000 bytes，因此不能同時填滿所有單格上限。
- 圖表：標題 600、各軸標籤 120、文字來源 12,000 bytes。流程圖 1–40 節點、0–80 連線；統計圖 1–5 數列、1–24 列資料，圓餅圖限單一非負數列且總和大於零。完整作品 JSON 及投影各最多 60,000 bytes。
- 心智圖：1–80 個已入圖節點、全圖 0–24 個待選分支，節點名稱 240、說明 2,000 bytes；完整作品 JSON 與文字投影各最多 60,000 bytes。單根、連通、不可循環；待選分支的父節點必須已入圖，不能直接再接待選分支。
- 向量圖形：1–100 個物件，畫布寬高為 1–4096 的整數；標題 600、物件名稱 120、文字物件內容 4,000 bytes。每個多邊形 3–80、折線 2–80 個頂點；數值最多三位小數，超精度拒收而不默默四捨五入。完整原生 JSON 與緊湊文字投影各最多 60,000 bytes；伺服器最終序列化仍做位元組檢查，非預設 PHP 精度設定可能使其更早到達上限。
- 網頁：1–20 區塊，cards／faq 每區 1–12 條目；標題與區塊標題 600、眉標／按鈕文字 240、區塊內文 12,000、條目標題 600、條目內文 6,000 bytes。完整正規 JSON 與文字投影各最多 60,000 bytes，總量包含結構及跳脫字元，超限整筆拒收不截短。
- 圖文／海報：完整原生 JSON 與相容文字投影最多 60,000 bytes，標題 600 bytes。圖文 1–24 區塊，段落標題／圖說各 600、內文 12,000 bytes；海報 2–16 區塊，至少一個標題加一個文字或圖片區塊，標題／文字區塊 2,000、圖片圖說 600 bytes。
- 互動視覺：1–40 個矩形／橢圓／直線圖層、0–24 個參數，畫布寬高 1–2048 整數，作品播放時間 1–60 整數秒；標題 600、圖層／參數名稱各 120 bytes。數字最多三位小數；參數目前／前次值須在範圍內並符合步進，完整原生 JSON／投影各最多 60,000 bytes。
- 圖片文字中繼資料：標題 600、替代文字 3,000、來源註記 2,000 bytes；圖片本體另受上述媒體配額及記憶體檢查限制。
- HTTP JSON 請求仍最多 1 MiB；專案序列化資料最多 2,000,000 bytes。每項目最多 60 版本（含封存）及 60 比較，對話、引用與其他容量限制見[架構](docs/ARCHITECTURE.md)。
- 圖片上傳使用獨立 multipart 端點，限 4 MiB PNG 加少量中繼資料，不放寬 JSON API。兩家 adapter 接受 6,000–24,000 output tokens 的路徑預算；這是請求上限，不保證模型支援、實際產出字數或符合格式。

- Ollama 僅接受 PHP 主機同機 loopback HTTP，固定 `/api/chat`、`/api/tags`，不接收 OpenAI Key。
- 「讀取模型清單」與連線檢查只在明確操作後讀取模型資訊，不推論、不下載模型。可手填模型名，但清單可見或連線成功不等於結構化輸出、品質或硬體效能驗收。
- 不自動重試、換模型、換供應者或使用示範答案。明確拒收與連線／寫入結果未知分開提示；拒收也可能已產生服務費用。

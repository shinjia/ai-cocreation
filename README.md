# AI共創工作室

以專案為核心的繁體中文共創工作台。每個專案可放多個創作項目，透過對談、方向確認、候選微調、比較與明確採用，保留使用者的判斷和完整版本歷程。

**第一階段本機試作版｜PHP 7.4 相容語法／SQLite／OpenAI Responses API 或本機 Ollama／HTTP 網頁安裝。** 一般使用不需 CLI、Node、npm、Composer 或 MySQL。沒有帳號與團隊權限，只能在 PHP 主機本機使用，不可公開部署、開放區網、反向代理或隧道。

## 第一階段範圍

創作類型依登錄與介面順序如下：

1. 標題名稱（`titles`）：已實作。
2. 短文（`short_text`）：已實作。
3. 長篇文章（`article`）：已實作。
4. 圖文（`illustrated`）：規劃中，尚未實作。
5. 表格（`table`）：規劃中，尚未實作。
6. 圖表（`chart`）：規劃中，尚未實作。
7. 心智圖（`mindmap`）：規劃中，尚未實作。
8. 向量圖形（`vector`）：規劃中，尚未實作。
9. 圖片創作（`image`）：規劃中，尚未實作。
10. 海報設計（`poster`）：規劃中，尚未實作。
11. 網頁（`webpage`）：規劃中，尚未實作。
12. 互動視覺程式（`interactive`）：規劃中，尚未實作。

後九種只可保存項目名稱、說明和固定版本引用，不提供生成、比較、融合或定稿，不用文字假裝已生成圖片、網站或程式。

## 專案、模型與歷史

- 專案保存共同名稱、說明與進度；每個創作項目各自保存對話、主軸、版本、正式版、比較與定稿紀錄，版號獨立。
- 在系統設定管理 AI 成員稱呼、服務、模型與啟用狀態，建立專案時一次選定成員／模型，專案內各項目固定共用，不逐句換人。沒有啟用成員時可先建空專案，完成設定後須明確綁定一次；舊未綁定專案也採相同流程，不推測原用模型。
- 綁定後若中央清單的原成員遭刪除、停用，或服務、模型、本機網址與綁定不同，AI 操作會阻擋。須恢復原設定；要使用其他模型請另建專案，不暗中替換。
- 每次 AI 結果保存當時成員與模型來源；歷史快照不隨中央改名或設定變動而重標，未回報的實際模型不猜測。
- 只有標題名稱在明確採用正式版時，才以主要名稱同步更新創作項目名稱。短文、長篇文章不因採用而更名；任何類型都不會因此改寫專案名稱／說明。

## 共創流程

工作區先顯示目前正式版完整內容，下方依序為「01 對談」「02 主軸與方向」「03 候選」，另有版本微調工作區及比較紀錄。長內容可捲動閱讀，版本依主版分組展開，保留小版本、實際來源與融合來源。

1. 說明用途、對象、核心訊息或限制。AI 在同一次討論回覆判斷方向是否足夠，足夠就整理待確認主軸；不足才釐清必要資訊，不要求固定三輪，也不另呼叫一次模型只判斷就緒。
2. 閱讀主軸，明確按「確認方向並生成候選」才開始生成。可以繼續討論，不會因方向備妥而自動生成。標題名稱每次 3–5 組、短文 3 篇、長篇文章 1 篇完整候選。
3. 可直接選候選或正式版繼續微調，不必先採用。AI 修改另存完整小版本；單純評價／釐清不建立假修訂，不覆寫來源或正式版。
4. 短文以「全文」一欄完整修訂。長篇文章先選來源版本，再明確勾選段落；AI 看見來源全文，但只回傳選取段落，伺服器逐位元組保留未選原文，合併保存完整文章快照。未選範圍不預設全選。
5. 手動編輯可另存新主版或小版。文章可在手動完整編輯區新增、移除或改名段落；這與 AI 選段修訂不同，AI 不得藉選段操作改變段落結構。新段落用新 ID，既有段落保留 ID。
6. 比較與融合是兩個獨立操作，都需選 2–5 個未封存版本。比較依各版自身的目標、修改意見與內容說明取捨，不以目前共同目標統一排名；明確按融合才另行呼叫 AI，保存一個新主版本候選及全部來源，不自動選勝者或取代正式版。
7. 使用者明確選正式版、項目定稿或專案結案。封存／還原不刪歷史；正式版不能封存。重新開啟仍保留過往定稿快照。尚未實作的規劃項目不自動算完成，可先封存再結案。

每版有單一「本版目標與修改意見」欄，最多 12,000 UTF-8 bytes；修訂與比較優先使用它。舊分欄僅相容呈現，不重寫歷史、不疊加重複標籤。AI 生成與修訂的目標整理取自同一次回覆，不額外推論。

AI 明確提供的單選問題可直接按答案，亦可自由輸入；舊紀錄不補造選項。答案綁定當時項目、脈絡、來源版本及文章選段，過期選項不能送出。點答案不清除尚未送出的文字草稿。

## 固定引用與容量

可明確引用同專案其他項目的某個未封存版本，保存完整內容與模型來源的固定快照。來源後來改版、封存或換正式版不會自動更換引用；需要新版時，移除舊引用再加入。AI 只能參考，不能修改被引用作品。

以下為 UTF-8 位元組，不是中文字數：

- 標題名稱：1–12 個自訂內容欄位，每欄 6,000、合計 24,000 bytes。
- 短文：固定 `body／全文` 一欄，最多 12,000 bytes。
- 長篇文章：1–80 段，每段 6,000、完整保存合計 120,000 bytes。單次 AI 生成／融合限 36,000 bytes；AI 選段修訂的來源段落合計限 24,000 bytes，回傳選段合計限 36,000 bytes，且不得超過全文扣除未選段落後的剩餘容量。超限拒絕，不悄悄截短或用摘要冒充全文。
- HTTP JSON 請求最多 1 MiB；專案序列化資料最多 2,000,000 bytes。每項目最多 60 版本（含封存）及 60 比較，對話、引用與其他容量限制見[架構](docs/ARCHITECTURE.md)。
- 兩家 adapter 接受 6,000–24,000 output tokens 的路徑預算；這是請求上限，不保證模型支援、實際產出字數或符合格式。

## AI 設定與安全

先閱讀並勾選系統設定中的資料傳送／費用說明。之後明確送出對談、生成、比較或融合便使用專案固定模型，不逐次彈窗。新增啟用成員或更換服務、模型、目的地需重新核對同意；建立專案、綁定、開頁面及保存設定本身不推論。

- OpenAI Key 只在專用密碼欄輸入，於 Web root 外的私有伺服器工作階段暫存，最多 30 分鐘。OpenAI 成員共用該工作階段 Key，不存進資料庫、成員清單、匯出或程式設定。API 費用與 ChatGPT 訂閱分開。
- Ollama 僅接受 PHP 主機同機 loopback HTTP，固定 `/api/chat`、`/api/tags`，不接收 OpenAI Key。
- 「讀取模型清單」與連線檢查只在明確操作後讀取模型資訊，不推論、不下載模型。可手填模型名，但清單可見或連線成功不等於結構化輸出、品質或硬體效能驗收。
- 不自動重試、換模型、換供應者或使用示範答案。明確拒收與連線／寫入結果未知分開提示；拒收也可能已產生服務費用。

## 安裝、更新與驗收

先讀[開始使用](開始使用.txt)，再看[安裝](docs/INSTALLATION.md)、[使用指南](docs/USER-GUIDE.md)、[安全邊界](docs/SECURITY.md)及[測試報告](docs/TEST-REPORT.md)。公開原始碼：[shinjia/ai-cocreation](https://github.com/shinjia/ai-cocreation)。下載 ZIP 後可將資料夾改名為 `ai-cocreation-series-php74`，使用文件中的本機網址；公開原始碼不代表公開部署。

**同系列既有安裝請安全覆蓋升級，不要重裝。** 停止寫入、清除暫存 Key 並備份原程式、`config.local.php` 及私有資料；合併覆蓋新版程式，不先刪舊資料夾、不覆蓋設定或資料、不重設資料庫，保留原網址及瀏覽器 Cookie／Session。前端快取標籤為 `20261021-version8`，必要時強制重新整理，不清除 Cookie。

舊 Vn 保留 ID、內容與來源，讀作主版本 Vn；舊 `article` 項目現在可使用文字功能，不改寫歷史。缺少 `aiBinding` 的專案讀為未綁定，須明確選一次，不能從歷史或中央目前選人自動推定。舊單一 AI 設定可轉成「原有設定」成員，首次仍需明確使用同意。

本次環境沒有原生 PHP runtime，未完成 PHP／Apache／XAMPP、實機瀏覽器或真實 OpenAI／Ollama 驗收，沒有使用真實金鑰或公開部署。來源、SQLite 與模擬檢查不等於實機通過；不能保證所有模型都能遵守輸出格式。

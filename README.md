# AI 共創室

以專案為核心的繁體中文共創工作台。每個專案可放一個或多個創作項目；使用者透過對話、比較與選擇參與創作，而不是只按生成。

**本機試作版｜PHP 7.4 相容語法 / SQLite / OpenAI Responses API 或本機 Ollama / HTTP 網頁安裝。** 不需 CLI、Node、npm、Composer 或 MySQL。沒有帳號與團隊權限，只能在 PHP 主機本機使用，禁止公開、區網、反向代理或隧道。

## 本次交付邊界

- 已實作專案新增、編輯、重新開啟，以及多個創作項目的新增、選取、封存與還原。這些專案層功能保留，不因工作區簡化而移除。
- 第一個可實際共創的類型是「標題名稱」。一個版本保存 1–12 個可自訂名稱的文字項目，不是固定四欄。中文名稱、英文名稱、Slogan、介紹短文只是例子。
- 文章、海報、網頁、互動程式目前只有規劃位置，可保存名稱、說明與固定版本引用。**尚未提供這些類型的生成器，不會假裝能生成圖片、網站或程式。**
- 這是架構與第一個文字創作能力的階段交付；不是所有創作類型都已完成。

## 專案、創作項目與內容項目

1. 專案：有自己的名稱、說明、進度；提供共享脈絡。
2. 創作項目：例如品牌命名、活動命名、海報規劃。每個都有自己的對話、目標、候選組、正式版、比較與定稿歷程。
3. 內容項目：某個命名候選組內的具名文字，例如「活動名稱」「開場提問」「行動邀請」。由討論與目標確立，穩定 ID 保留跨版本關係。工作區不再提供巢狀的「新增內容項目」按鈕，但既有自訂欄位與文字完整保留。

名稱與文字生成不會改寫專案名稱。明確採用正式版時，會以該版主要名稱同步更新創作項目名稱，左側項目卡片及目前項目標示隨之更新；專案名稱與說明保持不變。單純生成、修訂或另存候選不更名，切換創作項目不會把對話或版本混在一起。

## 本次修正：單欄編輯、通用創作者與回覆驗證

工作區步驟為「04 選擇與微調」、標題為「編輯創作內容」，只用一個「本版目標與修改意見」輸入框，最多 12,000 UTF-8 bytes。舊版分欄內容完整帶入，完全相同文字只顯示一次；重複編輯另存不疊加標籤，舊快照不改寫。

介面、示範及 AI 提示詞適用一般創作者，不預設使用者身分。AI 成員選單放在「和 AI 慢慢聊」區塊內、標題下方，位於討論紀錄與輸入欄之前。釐清回覆驗證已調整有界說明文字、引述標點及不需追問時的空問題處理；真正修改仍需完整可審閱的內容，不允許假稱已改動。已明確拒收的回覆不再誤顯示成結果未知，斷線／逾時仍保守處理。舊對話與使用者自訂文字不會重寫。這是程式契約修正，尚未經真實模型驗收，不能保證所有模型都能輸出有效格式。

## 共創流程

- 左側約 1/3 保留完整對話；右側約 2/3 展示目標、正式版、候選組及工作區。窄螢幕依序堆疊。
- 一次只問一個重點，至少三輪後整理目標與這組內容要包含的項目。使用者確認後，才可另外按「產生候選」。
- 每次產生 3–5 組新候選，舊候選並存，不自動取代正式版。工作區保存全部內容，不逐欄保存。
- 每個創作項目獨立編號。按「另存新版本 V?」建立下一個主版本，例如 V5；選定來源後按「另存小修改 V?.?」建立該主版本的下一個小版本，例如 V5.1。兩種操作都保存完整內容與來源關係，不覆寫原版。
- 選為正式版後可在對話中直接要求修改，產生完整、可審閱的新修訂；看過差異並採用後，下一輪從新的正式版繼續。普通釐清不假裝改動，日常修訂不必重走目標確認。
- 每版保存自己的「本版目標與修改意見」及來源對話。合併內容是後續修訂／比較的主要依據，舊分欄保留相容歷史，不蓋過新版意見。AI 候選／修訂仍用同一次回覆整理合併內容，不額外呼叫；手動另存前在同一欄調整。
- 可以選 2–5 個未封存的正式／候選版本，請 AI 依各版自己保存的目標與變更評估內容一致性、優點、取捨與建議。不套用目前共用目標統一排名，也不要求先重新確認目前目標。
- 暫時不採用的候選可封存及還原，正式版不能封存。封存不刪除內容、來源、過往比較或固定引用，也不釋放版本額度。
- 只有使用者明確操作才會升為正式版、將項目定稿或結案專案。重新開啟後歷史與舊定稿快照保留。
- 已封存項目不計入專案結案條件，且可還原；其資料沒有刪除。尚未實作的規劃項目不會自動算完成。

## 明確的跨項目引用

可把同專案另一創作項目的某個版本加入目前項目。引用包含來源項目、版本 ID、完整內容、模型來源與固定時間。來源後來改版、換正式版或重新開啟，都不會改掉已固定的引用。要採用新來源，請明確移除舊引用並加入新版本。AI 看得到被引用的文字，但不能修改來源作品。新增引用只列出未封存的來源版本；來源之後封存不會移除已固定的引用。

## AI 與模型

系統設定用 AI 成員清單管理稱呼、OpenAI／Ollama、模型和本機服務位置；勾選啟用後，才會出現在對話區成員選單。每位成員有穩定 ID。改稱呼、換模型或停用不會重標舊回覆；新回覆、候選與比較保存當時成員 ID／稱呼、供應者、要求模型、實際回報模型及時間。未回報的實際型號不猜測。

- 初次設定需閱讀並勾選資料傳送與費用說明。保存這份非秘密同意後，明確按「送出」、整理目標、生成或比較就直接使用所選成員，不逐次跳出確認視窗。未同意、沒有啟用成員或尚未選人時會阻擋呼叫。新增啟用成員或更換服務、網址、模型時，需重新核對並勾選設定中的同意，不是每次操作都詢問。
- 選擇成員、開啟頁面、保存設定不會自動推論，不輪流呼叫多個成員，也不暗中改用另一個模型。
- 可按「讀取模型清單」讀取服務回報的可用模型資訊；不自動查詢、不編造清單，也可手動輸入模型名稱。查詢失敗不改成示範清單，最近輸入紀錄不是可用性證明。
- OpenAI 成員共用本次工作階段的暫存 Key，不各自保存金鑰；Key 仍只在私有伺服器工作階段暫存，最長可用 30 分鐘。一次性使用同意不代表長期保存金鑰；API 計費與 ChatGPT 訂閱不同。
- Ollama 只接受 loopback HTTP 服務，固定 `/api/chat` 與 `/api/tags`，沒有自訂遠端 API 目的地，也不會把 OpenAI Key 傳給 Ollama。
- 可用模型查詢及連線檢查只讀取模型資訊，不做推論、不下載模型。成功不代表已驗證 Responses／結構化輸出、創作品質或足夠硬體效能。
- 不自動改供應者、不自動重試、不在錯誤時暗中使用示範答案。

# 讓自己的判斷留在共創裡

## 先有專案，再指定創作項目

例如「校園影展」是專案，名稱與說明交代共同背景。裡面可以建立「活動命名」「單元命名」兩個已可操作的文字項目，以及「主海報」「活動網頁」兩個尚未開放生成的規劃位置。

標題名稱項目內的候選不是單一句話，而是一整組可自訂的文字：活動名稱、英文名稱、Slogan、開場提問、行動邀請等。這些都是例子，不是必填四欄。

## 討論與採用新項目

可以先說「我想讓它像一個邀請，而不是公告」。AI一次追問一個重點。你也可以問「除了名字，還有什麼文字可以幫人理解？」；AI的提議不會立刻改作品。把要採用的項目講清楚，整理目標後確認，才進入候選生成。

第一次選定正式版之前，新的對話會使舊目標確認失效，原版本仍保留。選定正式版後，對話改為持續修訂：日常修改不必重走三輪討論或目標確認。專案、項目或引用脈絡變更仍會使目標確認失效，但不會阻止你針對既有正式版修訂；新一批初始候選、比較及定稿仍需確認目前目標。

## 選為正式版後，持續修改

「正式版」是你目前採用的工作版本，不是鎖住的定稿。可以在左側直接說「把中文名稱改成『日常有光』，其他項目不變」或「請縮短這段說明，語氣更口語」。

- AI使用當下正式版的完整內容組、專案脈絡、固定引用與這次要求修訂，不只修改第一個標題。
- 明確修改要求會產生一個新的「待採用修訂」，右側顯示整組內容、逐項前後差異、來源版本與模型。
- 按「採用這次修改」才把它升為正式版。原正式版、所有候選及對話都保留。
- 下一輪仍以當時的正式版為起點。若要接著改這次結果，請先採用；未採用的修訂不會悄悄成為下一輪起點。
- 單純詢問評價、意思不明或需要補充資訊時，AI只釐清，不建立假版本，也不假稱修改完成。
- 即使舊版對話曾讓目標變成待確認，只要已有正式版，仍可繼續AI修改或手動另存；不必另建專案。這不會假造新的目標確認。
- 原有自訂項目的ID與名稱會保留。需要刪除或重新命名內容項目時，可在手動編輯區調整、另存，再採用。
- 真正按過「此項目定稿」或整個專案結案時，需先按對應的重新開啟按鈕，所有舊定稿快照保留。

示範頁只支援畫面明說的文字替換腳本，不是真實AI改寫。

## 保存與比較

- 每一組候選都有來源說明、當時目標、對話連結和模型來源。
- 手動編輯可以增加自訂項目。按保存才成為新版本，不會悄悄修改舊候選。
- 比較時可以選正式版加兩個候選，問「哪組更像給第一次參加的人看的？」AI提供理由與代價，不替你決定。
- 升為正式版只代表你目前選擇它；後續產生候選不會動它。
- 項目定稿後內容鎖住；若想修改，先重新開啟討論。舊定稿快照不刪。

## 引用而不偷改

在另一創作項目明確選來源項目與版本，加入引用。畫面會保留來源與內容快照。來源後來改名或換正式版，引用仍是你當時選的那一版。請自行選擇是否換成新引用。

本階段海報、網頁、文章與互動程式只有規劃位置；引用文字並不代表系統已能生成海報或網頁。

## 模型可以換，歷史不重標

對話區切換「下一次」的AI服務與模型，只影響後續呼叫。歷史回覆仍顯示當時使用的模型。真正服務回報的名稱與你選的名稱不同時會分別保存；未回報時不猜測。

示範模式是固定腳本，沒有理解或真正生成能力，也不連接你的實際資料庫。它只示範按鈕與資料關係；關閉或重整後重置。

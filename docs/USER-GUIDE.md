# AI共創工作室使用指南

## 1. 設定成員，為專案固定模型

先在「系統設定」新增 AI 成員稱呼、服務、模型，勾選啟用，並閱讀／勾選資料傳送與費用說明。OpenAI Key 只能放在專用密碼欄，於 Web root 外私有工作階段暫存最多 30 分鐘，該工作階段的 OpenAI 成員共用；不要把 Key 放在對話、作品或一般設定檔。

「讀取模型清單」及連線檢查只讀服務資訊，不推論、不下載模型。可以手填模型名；清單可見或連線成功不保證結構化輸出、品質或效能。Ollama 必須已在 PHP 主機同一台電腦運作且有模型。

建立專案時一次選定 AI 成員／模型，所有創作項目共用，對談區顯示固定模型，不提供每句切換。沒有啟用成員時可先建空專案；完成設定後，和舊未綁定專案一樣，明確按一次「選定模型，開始共創」。已綁定專案不能重新選模型。

原成員刪除、停用，或中央模型／服務／網址與專案綁定不一致，都會阻擋 AI 操作，不自動找替代模型。請恢復原設定，要用另一模型則另建專案。中央改名不重標舊專案綁定或歷史來源；舊回覆未記錄的型號不補造。

首次設定同意後，明確按送出、生成、比較或融合即使用固定模型，不逐次彈窗。新增啟用成員或更改服務、模型、目的地需重新核對同意。建立專案、綁定、保存設定或開頁面本身不呼叫 AI；OpenAI API 費用與 ChatGPT 訂閱分開。

## 2. 專案與創作項目

專案名稱和說明是共同背景，例如「社區影像展」。底下可有活動命名、邀請短文、策展文章等獨立創作項目，各自保存對談、方向、版本、比較與定稿。

類型依序為：標題名稱、短文、長篇文章、圖文、表格、圖表、心智圖、向量圖形、圖片創作、海報設計、網頁、互動視覺程式。十一類已有功能，新增圖文／海報的文字與既有圖片排版；圖片限外部上傳、保存與實際分析，不提供 AI 像素生成／修改／融合。互動視覺程式只是規劃位置，尚不能生成或定稿。「共聊」不在本次範圍。

- 標題名稱：保存一組 1–12 個自訂文字欄位，例如名稱、Slogan、說明，不是固定四欄。
- 短文：一個 `body／全文` 欄位，保存完整短文。
- 長篇文章：依主軸形成段落／條款大綱，每段有固定 ID 和名稱，保存完整正文，不把大綱當作成品。
- 圖文：完整段落搭配同專案明確引用的固定圖片，提供純文字及上／左／右圖文排列，可手動完整編輯與含圖 HTML 匯出。詳見第 12 節。
- 海報：先分別確認視覺風格、完整文字與圖文排列，再生成可編輯的標題／文字／固定圖片區塊；不是 AI 產圖或固定尺寸印刷檔。詳見第 12 節。
- 表格：獨立的欄、列與文字儲存格，不是把表格塞進一般文章欄位。
- 圖表：以流程圖為預設，保存可編輯的受限 Mermaid 文字來源與圖表設定；也可明確使用 TSV 統計模式。

- 心智圖：以一個主題起步，已入圖節點與 AI 待選建議分開保存，勾選並加入草稿後才入圖，也可自行填寫分支。
- 向量圖形：由獨立幾何與文字物件組成，可修改屬性、圖層與畫布，另存後匯出保留原生圖形的 SVG。
- 圖片：自己選 PNG／JPEG，先本機準備再明確上傳成版本；可編輯文字中繼資料、請固定模型看圖討論／比較及下載 PNG，不能由 AI 改圖。詳見第 11 節。
- 網頁：先逐一確認視覺風格、內容結構與操作功能，生成可編輯原生響應式單頁；提供固定主題、頁內導覽、可展開 FAQ 及獨立 HTML 匯出。

## 3. 對談、主軸與候選

以下「確認並生成」、AI 像素修改及融合流程不適用圖片。圖片用外部上傳建立候選，AI 只提供分析與文字建議；「確認圖片方向」不生成圖片，詳見第 11 節。

正式版完整內容永遠在工作區頂部；下方為「01 對談」「02 主軸與方向」「03 候選」。桌面並列對話與工作內容，窄螢幕依序堆疊，長正式版可用鍵盤聚焦後捲動閱讀。

先說明用途、讀者、核心訊息或限制。AI 在同次回覆判斷方向是否足夠，足夠就整理待確認主軸，必要時才問一個重點。沒有固定三輪門檻，不要求填滿所有非必要資訊，也不因方向足夠而自動生成。

確認方向符合你的意思後，按「確認方向並生成候選」；這個明確操作才確認方向並呼叫一次生成。也可繼續討論，新的初次構思對話會更新待確認方向。標題名稱每次 3–5 組、短文 3 篇；長篇文章、表格、圖表、心智圖、向量圖形、網頁、圖文與海報每次各 1 份完整候選，全部保留，不自動指定正式版。心智圖只要有可探索的主題就能開始，其他資訊可保持未知，不必先選定唯一方向。

網頁需在方向區分別勾選「視覺風格」「內容結構」「操作功能與限制」，三項都確認後才可生成。單純勾選不呼叫 AI、不保存作品；新方向會重設勾選，詳細流程見第 10 節。

海報在方向區分別勾選「視覺風格」「完整文字內容」「圖文排列」，三項都確認後才可生成；與網頁三項不同，新方向同樣使舊確認失效。詳見第 12 節。

若 AI 明確提供單選答案，問題下方會顯示 2–6 個按鈕，可直接回答或自行輸入。按鈕名稱與完整答案不同時會同時顯示。只有最新、脈絡仍有效的問題可作答；切換來源版本、文章選段、心智圖探索節點或相關脈絡後舊選項會失效。按答案不清空輸入中的草稿，選答案也不等於採用作品。

## 4. 從任何候選或正式版繼續微調

按版本上的「以此版繼續微調」，或在編輯區選「工作來源版本」。候選不必先採用；未另選來源時，AI 延續目前正式版。畫面顯示來源後，再回到對談提出具體修改。

- 標題名稱：以整組欄位為修訂單位，完整保存自訂內容。
- 短文：以完整全文為單位，不只保存變動片段。
- 長篇文章：選好來源後，勾選要改的段落或條款，沒有預設全選。AI 看見來源全文來理解上下文，只回傳所選段落；其餘原文字節、順序和既有 ID 保持不變，伺服器合併成完整新快照。沒有勾選就不呼叫修訂。

表格與圖表以完整作品為修訂單位，不用文章選段。請先選來源，再說明要改哪些欄列、節點、連線或呈現；結果保存完整結構化作品，不只保存變更片段。沒有資料時先釐清，不能用編造數字補滿統計圖。

心智圖的 AI 微調只為對談區選定的已保存節點提供待選子分支；節點改名、說明、移動與合併改用手動工作區。待選建議不是已入圖內容，操作順序見第 8 節。

向量圖形以完整已保存作品為修訂單位。先選來源，再說明要改的圖形、位置、尺寸、配色或文字；AI 不讀未另存草稿，不使用文章選段，也不另接圖片服務。完整物件編輯與匯出見第 9 節。

網頁以完整已保存頁面為修訂單位，可調整風格、區塊、文字及支援的頁內功能，不接受文章選段，也不執行任意程式。AI 不讀未另存草稿；完整操作見第 10 節。

圖文與海報以完整已保存排版為修訂單位，可改完整文字、主題、區塊排列與明確提供的固定圖片選擇；模型只看文字中繼資料，不讀圖片像素或未另存草稿。完整操作見第 12 節。

圖片選來源後只供看圖討論，不建立 AI 像素修改版；要改圖片請在外部工具編輯後重新明確上傳，或只手動修改文字中繼資料。

前述可修訂類型中，AI 明確改寫會新增來源主版下的小版本，例如從 V2 另存 V2.1，附差異及本版目標，尚未取代正式版。可直接選新候選再改，不需先採用。若只是評價或必要釐清，就保留討論，不建立假版本。修訂既有候選或正式版不要求重走初次方向確認。

文章 AI 選段操作不能新增、刪除或改名段落，也不能修改未選範圍。若要改結構，請改用完整手動編輯區，再另存新版本。手動可改正文、段落名稱或新增／移除段落；已有段落保留 ID，新段落取得新 ID，來源不變。

已啟用類型的手動修改都可「另存新版本 V?」或以選定來源「另存小修改 V?.?」。兩者保存完整內容，不是直接覆寫。草稿尚未另存時只在目前頁面，重新整理可能遺失。

「本版目標與修改意見」合併在一欄，最多 12,000 UTF-8 bytes，從選定來源帶入。舊版不同欄位合併呈現、完全相同文字不重複，原快照不改。新保存內容是後續修訂與比較的主要依據，不被目前共用目標或舊相容欄位蓋過。

## 5. 版本樹、比較與融合

候選區按主版本分組，可展開完整內容與來源。小版本沿來源主版編號，但實際來源可能是該組任一版，請看「實際來源」；融合會列全部來源，不靠相鄰版號推測關係。正式版亦保留在歷程中，並可跳回頂部閱讀。

勾選 2–5 個不同、未封存的版本，可包含正式版與候選：

- 比較：獨立請 AI 依每版自己的目標、討論變更、修改意見與完整內容評估。目標不同會說明取捨，不按目前共同目標統一排名，也不因較新或正式版身分自動加分。比較不要求重確認目前方向，不修改版本。
- 融合（圖片尚未提供）：另填想保留的優點／方向，再明確按「融合所選版本為新候選」。這是另一次 AI 呼叫，保存一個新主版本、完整內容、採納／捨棄說明與來源快照。比較不會自動觸發融合，融合也不會直接變正式版。

候選可以封存及還原；正式版不能封存。封存不刪除、不釋放版本額度，也不改舊比較與引用。封存版本須先還原，才能當新的修訂、比較、融合或引用來源。

## 6. 採用、定稿、引用與匯出

明確按「設為正式版」才更換工作區頂部作品，不等於定稿。只有標題名稱採用時會依主要名稱同步更改創作項目名稱；短文／文章／表格／圖表／心智圖／向量圖形／圖片／網頁／圖文／海報不因此更名，所有類型都不改專案名稱或說明。生成、修訂、融合或手動另存也不更名。

項目定稿仍需有效的目前方向與正式版；已定稿或專案已結案時先重新開啟再改，舊定稿快照保留。專案結案要求所有未封存項目完成；尚未實作的互動視覺程式不算已完成，可先封存，不能假裝定稿。

可固定引用同專案另一項目的某個未封存版本。引用保存完整內容及模型來源，來源後來改版、封存或改正式版不會同步變動。要使用新來源，明確移除舊引用再加入新版。AI 不能改寫來源作品。

匯出 JSON 會包含文字、表格／圖表／心智圖／向量圖形／網頁／圖文／海報完整原生結構、歷史、引用、專案模型綁定與模型來源，不含 Key；分享前檢查未公開內容。作品依原瀏覽器工作階段辨識，遺失 Cookie／Session 後沒有帳號復原入口，重要內容應另存匯出。圖片只含中繼資料、不含 PNG，JSON 不是完整圖片備份；另下載 PNG，並在程式停止寫入時離線備份完整私有資料夾與設定，見第 11 節。

## 7. 表格、流程圖與統計圖

### 表格

在工作區直接改欄名、表格說明及各格文字，或按新增／移除列欄。保留的列欄會沿用 ID；新增項目取得新 ID。每格只保存文字，輸入公式不會計算，也沒有 Excel 樣式、合併儲存格或外部連動。修改後明確另存主版或小版，原來源保持不變。

### 流程圖（預設）

在「流程圖文字來源（Mermaid 子集）」編輯節點及連線，通過格式驗證後顯示本程式自己的 SVG 預覽。以下只是語法範例，不代表你的實際流程：

```text
flowchart TD
Start("開始")
Draft["整理想法"]
Review{"確認方向？"}
Done("完成")
Start --> Draft
Draft --> Review
Review -->|需要調整| Draft
Review -->|確認| Done
```

- `TD` 是由上而下，`LR` 是由左至右；也接受 `graph` 標頭和 `TB`（同 TD）。新建編輯器的單一「開始」是手動佔位節點，不是 AI 已完成作品。
- 節點逐行獨立宣告：方框 `A["文字"]`、菱形 `B{"判斷"}`、圓角框 `C("開始")`。ID 以英文字母開頭，只含英數及底線，最多 40 字元，不可重複或使用 `end`、`subgraph`、`click` 等保留字。
- 連線另占一行：`A --> B` 或 `A -->|標籤| B`。端點都必須有獨立節點宣告，不能邊連線邊宣告或串接多段箭頭。可有循環與自我連線，完全相同的連線不可重複。
- 只接受受限純文字標籤；含括號或分號時必須使用上例的外層雙引號，其他特殊標記仍不接受。支援空白行、一般 `%%` 註解與單一行尾分號；不支援子圖、樣式／class、click、初始化指令、HTML、Markdown、網址、圖片或任意程式。
- 此處不是完整 Mermaid 引擎。預覽使用簡化排版，複雜連線可能重疊；長標籤在圖上可能縮略，請核對下方完整節點／連線列表和來源文字。

### 可選統計模式

明確選長條、折線或圓餅圖，來源改填真正以 Tab 分隔的 TSV：第一列是分類名稱與數列名稱，後面每列是一個分類及各數值，不是 Markdown 表格。先提供數據及用途再請 AI 整理，缺數據時應釐清；不能用範例數字當成你的真實資料。流程圖不需要提供這些統計數字。

數值只接受有限十進位字串，可有正負號、小數；不接受公式、科學記號、千位逗號、數值前後空白、NaN 或 Infinity。圓餅圖限一個非負數列且總和大於零。切換流程／統計模式時會保留原來源，不自動轉換或刪除；格式錯誤的草稿仍留在編輯器，修正後才能保存。

### 匯出與固定腳本示範

版本上的按鈕只處理那個已保存版本，不含尚未另存的草稿，也不呼叫 AI：

- 表格：CSV／TSV 只含欄名與儲存格，不含表格說明、列欄 ID、樣式或版本歷史。
- 流程圖：MMD 保留文字來源；SVG 是目前簡化排版的圖形。MMD 不含另存的圖表標題與版本紀錄，SVG 也不是可重新編輯的完整專案。
- 統計圖：TSV 保留資料來源；SVG 是圖形，不含完整共創歷史。
- 圖表可按「複製文字來源」；若瀏覽器不允許剪貼簿，改匯出 MMD／TSV 後自行複製。沒有自動匯入、同步或連線圖坊，亦未驗證相容性。

CSV／TSV 匯出會為可疑公式文字加前置單引號；統計資料中已驗證的數字保持數值，包括負數。匯出後在試算表呈現可能與原字串不同，原始文字、結構、標題／說明及完整歷史請保留專案 JSON。

「固定腳本示範（非 AI）」中，圖表可選「使用流程圖示範」，或輸入「請使用流程圖示範。」；也可明確選虛構參觀人次統計示範。節點、時段與數字全部是虛構示範，不解析或代用你提供的真實資料。對話只支援逐字替換表格說明、圖表標題或本版目標；其他內容請直接編輯另存，示範比較／融合也不是模型分析。重新整理會重設示範資料。

## 8. 心智圖：從主題慢慢展開

### 先看建議，自己選擇

1. 建立「心智圖」項目，先說一個想探索的主題，例如「社區影像展有哪些可能方向？」。不必先決定唯一主軸或填滿用途／讀者等資訊，缺少主題才需釐清。
2. 主題方向符合你的意思後，按「確認方向並生成候選」。第一次只產生主題根節點和 2–12 個待選分支；畫面中的圖尚未包含這些建議，checkbox 全部預設未勾選。
3. 按候選上的「以此版繼續微調」，在工作區選根節點或其他已入圖節點。勾選喜歡的建議，再按「將勾選分支加入草稿」。單純勾 checkbox 還不會修改圖，沒勾選的建議繼續留在待選區，不要求一次用完。

## 9. 向量圖形：編輯物件，再另存 SVG

### 建立與選取

建立「向量圖形」項目，說明用途、要表達的內容和必要限制。方向足夠後先閱讀並確認，再產生一份完整候選。它使用專案原有文字／結構化模型，不另接圖片生成服務；適合基本幾何構圖、圖示與文字，不生成照片、點陣插畫或任意曲線。

### 修改畫布與六種物件

- 畫布：改作品標題、寬度、高度與背景，按「套用畫布修改至草稿」。作品標題是文件名稱，不會自動改寫圖內文字。
- 矩形／橢圓：X、Y 是外接框左上角，寬高必須大於零。
- 線段：X、Y 是起點；水平／垂直位移決定終點，可為負數，例如水平位移 -100 代表向左 100。
- 多邊形／折線：在「局部頂點」每行填一組 x,y，先依物件 X、Y 平移。多邊形至少三個、折線至少兩個頂點，每個物件最多 80 個；不支援自由 path 或貝茲曲線。
- 文字：X、Y 是首行文字基線，改「圖形文字」與「文字大小」；保留文字及換行，使用通用字型，不載入外部字型。
- 每個物件都可改名稱、填色、外框色／寬度、不透明度。色彩只用 #rrggbb（如 #245c91）或 none；線段要改可見顏色，請改外框色而非填色。數值最多三位小數，不接受科學記號、數字前後空白或不完整數字，也不自動四捨五入。

改好後按「套用圖形修改至草稿」。套用前的欄位不是已保存作品；錯誤值會留在欄位讓你修正，不會改壞目前有效圖形。畫布外的物件可能看不見，但原生資料及完整清單仍保留，可再改位置移回。

選擇類型後可新增圖形；複製會建立新 ID，但位置相同，可能與來源完全重疊，可修改座標分開。圖層清單由後至前排列，「向前移一層」更靠近觀看者，「向後移一層」相反。可移除選定物件，但至少保留一個物件。

固定腳本融合只追加相容區塊；主題／導覽設定不同或同 ID 區塊內容衝突會拒絕，不擅自取捨、改名或丟資料。這不是模型品質驗收，重新整理會重設全部示範資料。

## 11. 圖片：自己上傳，再看圖討論與比較

圖片項目沿用前一圖片階段的外部上傳與分析能力，不是 AI 生圖工具。本次新增的圖文／海報原生排版見第 12 節；互動視覺程式仍是規劃位置。

### 第一步：在本機準備自己的圖片

1. 在正式頁新增「圖片創作」項目，使用「選擇 JPEG／PNG（只在本機準備）」選一張靜態圖片。不需 API Key，選檔不會上傳，也不會呼叫 AI。
2. 原檔最多 12 MiB、寬高各最多 8192 像素、總像素不超過 16,777,216。不接受 SVG、GIF、WebP 或 APNG；檔名改成 .png 也不會通過真正格式檢查。
3. 畫面先顯示本機 PNG 副本。程式依圖片方向縮到最長邊不超過 2048，不放大小圖；可再選 0／90／180／270 度順時針旋轉。副本須不超過 4 MiB，透明度會保留，原始檔不被改寫。
4. 檢查方向與畫面，再填「新圖片標題」及「這次上傳的本版目標與修改意見」，兩者必填，不自動套用檔名或專案目標。替代文字可描述重要畫面，來源註記可記錄出處與授權，但系統不代你驗證來源真偽或使用權。
5. 不想保存可按「取消本機圖片副本」。副本與欄位只留目前頁面，不是自動保存；關閉或重新整理可能遺失。先保存或取消，才能切換項目／專案或發出 AI 操作，準備中的圖片不會自動送進討論。

副本經瀏覽器轉換及伺服器正規化，不保留原始檔名、EXIF／IPTC／XMP 或色彩描述檔。縮圖、解碼、方向及色彩描述檔處理可能改變顯示色彩，不適合作為原始照片、印刷色彩或典藏忠實度的替代檔；請自行保留原始圖片。

### 第二步：明確保存為版本

按「保存圖片為新大版本」才把副本送到此安裝網站，建立完整新候選；若已選未封存來源，也可按「保存圖片為來源的小修改」。伺服器只接受經檢查的非交錯 8-bit RGB／RGBA PNG，會重驗、去除中繼資料、重新壓縮及計算雜湊。保存成功顯示「外部上傳圖片」，不是 AI 生成，不呼叫模型，也不自動改正式版。

小修改代表新版本的來源關係，不代表系統比對或修改了像素。想更換畫面，請在外部工具編輯好，再上傳新檔；原候選、正式版、封存／定稿與固定引用都保留原圖片。

若上傳發生斷線或回應不完整，先按畫面提示讀取最新紀錄，再決定是否「重試同一請求」。不要反覆重新選檔或連按保存，伺服器可能已保存成功；相同請求會用收據核對，避免另建重複版。這次上傳不呼叫 AI，沒有 AI 費用；停止追查也不會撤銷伺服器已完成的保存。其他分頁切換項目後，本機副本仍留在原項目，須明確返回或放棄，不能自動轉存。

### 只改圖片文字，不改像素

選已保存版本的「編輯」或「以此版繼續微調」，修改圖片標題、替代文字與來源註記。先按「套用圖片文字至草稿」，再用外層「另存新版本」或「另存小修改」保存；不想保留欄位可按「放棄圖片文字欄位修改」。本版目標也會隨新版本保存。

未套用欄位與已套用草稿都不等於持久版本，整頁重新整理或關閉可能遺失。手動另存只能沿用所選來源的同一 PNG，沒有裁切、調色、繪製、像素替換或 AI 生圖。修改標題也不會改寫圖內文字或創作項目名稱。

### 同意一次，之後用正常送出分析圖片

1. 先確認本專案既有固定模型。在「圖片分析的傳送範圍」閱讀接收服務／模型、真正 PNG 與相關專案文字將如何傳送、可能費用，再按「我同意此固定模型接收圖片分析資料」。這一步只保存同意，不呼叫 AI。
2. 選擇已保存圖片版本，輸入要討論的構圖、色彩、文字可讀性或用途，再正常按送出。也可從正式版按「請 AI 分析這張圖片」。已有一次同意後不再逐次彈窗，仍需要一般 AI 設定有效，以及 OpenAI 當次有效 Key（如使用 OpenAI）。
3. 圖片討論或整理方向會提供所選已保存來源與固定圖片引用的實際 PNG。未選來源、也沒有正式版或圖片引用時，只能討論方向，不代表 AI 已看過其他歷史圖片。未保存的本機副本、手動文字草稿不會送入模型。
4. 同一次最多 5 個不同圖片資產、PNG 原始位元組合計 12 MiB。兩個版本若沿用同一資產，像素只傳一次，版本目標仍分別保留。超限或記憶體不足請縮小圖片／減少引用，不會偷偷漏圖或自動改用文字描述。

選定模型須支援視覺輸入及所需結構化輸出，模型清單可見、連線成功或能聊文字不代表可以看圖。若不支援會顯示錯誤，不換模型或服務；需要不同模型時須另建專案。Ollama 雖限定同機入口，使用者自行設定的轉送可能傳到別處或收費。AI 也可能看錯細節、文字或色彩，請用實際畫面核對。

回覆只提供分析與文字建議，不改像素、不建假圖片版本、不自動採用。方向整理好後可按「確認圖片方向（不生成圖片）」供後續定稿使用，這個確認不呼叫 AI。「圖片生成尚未開放」與融合都不能執行，明確要求改圖也只會得到建議。

### 比較、固定引用、採用與定稿

選 2–5 個不同且未封存的圖片版本，再按「請 AI 提供比較意見」。比較使用各版自己的目標，傳送的像素只有所選版本；固定引用雖可能仍有文字脈絡，其圖片不額外混入本次比較。比較不選勝者、不新增圖片版，也不能直接融合成新圖。

分析／比較歷史保存此次使用的項目、版本、資產 ID 與 SHA-256，對應真正傳送的 PNG，不包含 PNG 本體。若固定引用另一圖片項目的舊版本，來源後來改版、封存或換正式版不會自動更新；需明確移除舊引用再加入新版。其他創作模組只使用圖片引用的文字中繼資料，不自動傳像素。圖文／海報可在本機排版預覽及 HTML 內嵌固定圖片，但不等於 AI 看過圖片；網頁仍不嵌入圖片。

按「設為正式版」才採用圖片；定稿仍需已確認方向與正式版。封存不刪圖片、不釋放容量，原定稿與引用仍可讀取相同資產。正式版不可封存；封存版本若要用作新的分析／比較來源，請先還原。

### PNG 下載不是原始檔，JSON 不是完整圖片備份

只有頂端正式版會自動載入圖片；候選、版本歷史、固定引用與比較內的其他圖片，請按「載入此圖片預覽」。這只從本機安裝網站讀取已保存 PNG，不呼叫 AI，不會一開頁就讀入全部歷史圖片。

已保存版本可下載伺服器正規化後的 PNG，不含未保存草稿，不呼叫 AI。預覽與下載經私人、同源且已驗證的讀取取得，沒有可公開分享的資產網址；畫面使用的 Blob URL 只供短暫本機顯示，不是分享連結。

專案 JSON 保留圖片文字、尺寸、雜湊、版本、引用與模型分析來源，但不含 PNG。「匯出圖片中繼資料 JSON」只保存該版的中繼資料，並不包含完整歷史，不能當完整圖片備份，也沒有檔案重新匯入／自動還原介面。

請另外保留原始圖片並下載所需 PNG。要備份整個工作室及全部歷史圖片，應先停止程式寫入，再離線備份整個私有資料夾（含資料庫及可能存在的 journal／WAL 檔）與 config.local.php，不只複製使用中的 SQLite 主檔。備份可能含 Session／仍有效 Key，須私密保管、不可當作品分享；同系列升級保留設定、資料、Cookie／Session 與仍有效 Key，不需重新安裝。

固定腳本示範不提供圖片上傳或真正圖片分析；請在正式本機安裝中驗收，不能把示範或測試替身當成真實看圖能力。

## 12. 圖文與海報：完整文字搭配固定圖片

### 先準備材料，不把排版當作生圖

在同一專案新增「圖文」或「海報設計」。兩者沿用此專案已固定的文字／結構化模型，不另設圖片服務、不生成、重繪或融合圖片像素。模型收到完整文字與排版結構，以及圖片標題、替代文字、來源註記、尺寸等中繼資料，不能視覺判斷真正的畫面、顏色或圖中文字。

若作品需要圖片，先依第 11 節在同專案「圖片創作」保存外部 PNG／JPEG 版本，再到圖文／海報的引用區明確選定該圖片項目與版本。單純有圖片項目不等於已引用；不自動拿別的作品、最新圖片或外部網址來補。沒有圖片時可以先做純文字排版，不能以假圖片、假網址或占位資產假稱完成。有需要真正看圖的問題，請在圖片項目另行明確同意分析後再問。

### 圖文的段落與海報的三部分方向

圖文在對談說明用途、讀者、完整內容及必要排列。方向足夠後先確認，再生成一份完整候選。每段包含可空的段落標題、完整內文與圖說；純文字排列不選圖片，有圖排列可用「圖片在上」「圖片在左」「圖片在右」。主題為紙感淺色（paper）、夜色深色（night）或草地綠色（meadow）。

海報在「02 主軸與方向」分開呈現：

1. 視覺風格。
2. 完整文字內容。
3. 圖文排列。

逐項閱讀並勾選後，再按「確認方向並生成候選」。勾選本身不呼叫 AI、不保存作品；新的方向或相關脈絡變動會清除舊勾選，不能沿用過期確認。海報三部分不是網頁的「內容結構／操作功能」。生成結果為一份完整海報，不是文字提案或不可編輯的點陣圖。

海報可選直式（portrait）、方形（square）、橫式（landscape），以及紙感淺色（paper）、夜色深色（night）、節慶暖色（festival）。區塊是標題、文字或固定圖片，各自靠左、置中或靠右；至少保留一個標題及一個文字或圖片區塊。版面會隨內容延展，不保證固定印刷尺寸、出血或單頁列印。夜色主題另有亮文字與圖說樣式，仍應在自己的瀏覽器檢查實際閱讀與列印效果。

### 明確套用、放棄與保存完整版本

1. 在候選或正式版按「以此版繼續微調」，不必先採用。作品標題、主題及海報版型放在「作品風格與設定」；選取區塊後可修改完整文字、圖片引用與排列／對齊。
2. 設定欄位改完按「套用作品設定至草稿」；區塊改完按「套用區塊修改至草稿」。若不要這些尚未套用的修改，按對應的「放棄作品設定欄位修改」或「放棄此區塊欄位修改」，不改已套用草稿或保存版本。
3. 先套用或放棄所有待處理欄位，再用「新增區塊至草稿」「上移區塊」「下移區塊」「移除區塊」。純文字區塊不可選圖片；圖文有圖排列或海報圖片區塊必須選到已保存的固定引用。新增文字是明示的可編輯草稿，不是生成完成的內容。海報不可移除到缺少必要標題／內容。
4. 檢查完整預覽與「本版目標與修改意見」，再按外層「另存新版本 V?」或「另存小修改 V?.?」。套用、選區塊、讀預覽與更換主題都不等於已保存，也不自動替換正式版。
5. 同頁切換區塊、忙碌重畫或讀取最新狀態會保留欄位草稿；整頁重新整理／關閉會失去未另存內容，不能當成持久保存。此排版編輯器沒有復原按鈕，需要回到原內容時可重新選擇已保存來源，先處理目前未保存修改。

目前引用與來源版原有的歷史圖片會一起供編輯使用。從目前清單移除引用，不會改掉舊版本的固定圖片；新保存版保留目前引用及其實際沿用的歷史圖片。若同一引用 ID 對應兩個不同快照，編輯會被阻擋，請重新選擇完整來源；不會猜測哪張正確或偷偷換成新圖。缺漏、來源不符或私人圖片驗證失敗時同樣停止，不能靠更改引用 ID 或匯入 JSON 繞過。

### AI 修訂、比較、融合與歷史

先選已保存來源，再提出要改的文字或排列。AI 讀完整來源，不讀頁面草稿，也不接受文章選段；未要求的內容應保持，結果另存完整小版。純評價、必要釐清或要求生圖／改像素時只提供討論，不建立假修訂。只有明確採用才改正式版；定稿、封存／還原與固定引用沿用共用流程。

比較及融合各自選 2–5 個不同、未封存版本，按各版自己的目標評估完整文字、原生排版及已知圖片中繼資料，不假稱視覺檢查了圖片。比較不改作品；另按融合才新增一份完整主版，保存全部來源及取捨，不合成圖片像素。單純換區塊 ID 或同一圖片版本的引用別名不算新作品。舊來源及原正式版不被自動覆寫。

### 私人預覽與 HTML／JSON／TXT

- 頂端正式版會自動載入其固定圖片；候選、歷史、引用與比較中的其他版，按「載入此排版圖片預覽」。編輯草稿另按「載入編輯草稿圖片預覽」。這只是從本機安裝的私有資料讀 PNG，不把圖片傳給 AI，也不是公開分享網址。
- 「下載完整排版 HTML」只使用該已保存版的完整文字、固定樣式與確切固定圖片。匯出前經私人介面讀 PNG，核對格式、尺寸、位元組長度及 SHA-256；缺圖、變更、不相符、失敗或頁面切換使操作過期時整筆停止，不產生缺圖檔案。沒有圖片的合法純文字作品仍可匯出，不用假圖片填補。
- 內嵌圖片原始位元組合計最多 20 MiB，依區塊實際出現次數計算，同一張圖重複使用也重複計入；每張仍最多 4 MiB。HTML 因 base64 編碼、文字及樣式可大於 20 MiB。超限不悄悄刪圖，請減少區塊用圖或先另存較小圖片版本後明確改用。
- 輸出的 HTML 是可離線開啟的獨立檔：安全跳脫文字、固定 CSS、內嵌 PNG，沒有 JavaScript、外部連線、外部圖片網址或表單。它包含實際圖片與來源註記，分享前檢查私人內容及圖片使用權；下載不等於已上線或已印製。
- 「匯出排版中繼資料 JSON」保存可編輯原生排版及固定引用 ID，但不含 PNG、引用來源完整版本或專案歷史。「匯出文字 TXT」保存完整文字與引用標記，不含圖片像素或視覺排版。沒有這些檔案的匯入／自動還原介面；單版 HTML／JSON／TXT 都不是完整專案備份。

完整備份仍依第 11 節：停止寫入後離線備份私有資料夾與設定，另保留原圖；備份含 Session／暫存 Key 時須私密保管。離線固定腳本示範明確不支援圖文／海報，必須在正式本機安裝驗收，不能以示範或來源檢查當成實機／真實模型已通過。

## 13. 容量與錯誤

全部限制以 UTF-8 位元組計，不是中文字數：標題每欄 6,000、合計 24,000；短文全文 12,000；文章 1–80 段、每段 6,000、保存全文合計 120,000。文章單次生成／融合上限 36,000；AI 修訂選段原文合計上限 24,000、回傳選段合計上限 36,000，且不得超過全文保留未選段落後的剩餘容量。手動長文保存上限不代表 AI 可一次生成同樣長度。

表格最多 12 欄、100 列，每格 2,000 bytes，欄名 120、說明 600 bytes。圖表標題 600、軸標籤各 120、來源 12,000 bytes；流程圖 1–40 個節點、0–80 條連線，節點文字 240、連線標籤 120 bytes；統計圖 1–5 個數列、1–24 列資料，標頭／分類名稱各 120 bytes、數值絕對值不超過 1 兆。表格與圖表的完整作品 JSON、文字投影各限 60,000 bytes，不能同時填滿所有欄格的單項上限。

心智圖最多 80 個已入圖節點、全圖 24 個待選分支；各名稱 240、說明 2,000 bytes，完整作品 JSON 與文字投影各最多 60,000 bytes。初次及每次新增待選子分支集合為 2–12 個。移動須維持單根、連通且沒有循環；合併後說明超限會整筆拒絕，不截短或刪其他內容。

向量圖形 1–100 個物件，畫布寬高各為 1–4096 的整數；標題 600、物件名稱 120、文字 4,000 bytes。X／Y 及局部頂點為 -4096 至 8192；物件寬高／線段位移為 -8192 至 8192，矩形與橢圓寬高須為正；外框寬度 0–100、不透明度 0–1、文字大小 1–512，數值最多三位小數。原生 JSON 與緊湊投影各最多 60,000 bytes；非預設 PHP 數字序列化精度可能令伺服器更早達上限，會整筆拒收而不改寫或截短。

網頁 1–20 區塊，cards／faq 每區 1–12 條目；網頁／區塊／條目標題各 600、眉標／按鈕文字各 240、區塊內文 12,000、條目內文 6,000 bytes。完整正規 JSON 與文字投影各最多 60,000 bytes，總量包含結構與跳脫字元，不能同時填滿所有欄位上限；超限整筆拒絕，不截短。

圖文 1–24 區塊，段落標題／圖說各 600、內文 12,000 bytes；海報 2–16 區塊，至少一個標題加一個文字或圖片區塊，標題／文字各 2,000、圖說 600 bytes。兩類作品標題各 600、完整原生 JSON 與投影各最多 60,000 bytes，保留原文字、空白、順序及穩定 ID。含圖 HTML 的 20 MiB 是按內嵌次數計算的 PNG 上限，不是模型或專案 JSON 配額。

圖片標題 600、替代文字 3,000、來源註記 2,000 bytes，本版目標仍限 12,000 bytes。每專案最多 100 張圖片資產／64 MiB、同一瀏覽器 owner 最多 400 張／256 MiB；封存仍計入，沒有自動清理歷史圖片。PHP 記憶體安全預留可能比名義容量更早拒收，請縮小圖片或減少分析張數，不要關閉限制。

主 JSON API 請求仍最多 1 MiB；圖片使用獨立 4 MiB PNG 加少量中繼資料的上傳通道。專案資料最多 2,000,000 bytes，每項目最多 60 版（含封存）和 60 比較。超限時不截斷原文；需縮小選段、縮短本次輸入，或先匯出再建立新項目／專案。模型 output tokens 請求預算為 6,000–24,000，不是字數或成功保證。

明確格式拒收不會被當作有效結果，舊資料保留，但上游仍可能計費。逾時、斷線或寫入結果未知時先查看最新狀態，不連按重試；系統不自動重試、換模型或以腳本冒充 AI。來源與模擬檢查不等於實測，本次未完成原生 PHP、Apache／XAMPP、實機瀏覽器或真實模型驗收。

# AI共創工作室使用指南

## 1. 設定成員，為專案固定模型

先在「系統設定」新增 AI 成員稱呼、服務、模型，勾選啟用，並閱讀／勾選資料傳送與費用說明。OpenAI Key 只能放在專用密碼欄，於 Web root 外私有工作階段暫存最多 30 分鐘，該工作階段的 OpenAI 成員共用；不要把 Key 放在對話、作品或一般設定檔。

「讀取模型清單」及連線檢查只讀服務資訊，不推論、不下載模型。可以手填模型名；清單可見或連線成功不保證結構化輸出、品質或效能。Ollama 必須已在 PHP 主機同一台電腦運作且有模型。

建立專案時一次選定 AI 成員／模型，所有創作項目共用，對談區顯示固定模型，不提供每句切換。沒有啟用成員時可先建空專案；完成設定後，和舊未綁定專案一樣，明確按一次「選定模型，開始共創」。已綁定專案不能重新選模型。

原成員刪除、停用，或中央模型／服務／網址與專案綁定不一致，都會阻擋 AI 操作，不自動找替代模型。請恢復原設定，要用另一模型則另建專案。中央改名不重標舊專案綁定或歷史來源；舊回覆未記錄的型號不補造。

首次設定同意後，明確按送出、生成、比較或融合即使用固定模型，不逐次彈窗。新增啟用成員或更改服務、模型、目的地需重新核對同意。建立專案、綁定、保存設定或開頁面本身不呼叫 AI；OpenAI API 費用與 ChatGPT 訂閱分開。

## 2. 專案與創作項目

專案名稱和說明是共同背景，例如「社區影像展」。底下可有活動命名、邀請短文、策展文章等獨立創作項目，各自保存對談、方向、版本、比較與定稿。

類型依序為：標題名稱、短文、長篇文章、圖文、表格、圖表、心智圖、向量圖形、圖片創作、海報設計、網頁、互動視覺程式。標題名稱、短文、長篇文章、表格、圖表這五類已有功能，其餘七類只是規劃位置，可保存名稱、說明與固定版本引用，尚不能生成、比較、融合或定稿。

- 標題名稱：保存一組 1–12 個自訂文字欄位，例如名稱、Slogan、說明，不是固定四欄。
- 短文：一個 `body／全文` 欄位，保存完整短文。
- 長篇文章：依主軸形成段落／條款大綱，每段有固定 ID 和名稱，保存完整正文，不把大綱當作成品。
- 表格：獨立的欄、列與文字儲存格，不是把表格塞進一般文章欄位。
- 圖表：以流程圖為預設，保存可編輯的受限 Mermaid 文字來源與圖表設定；也可明確使用 TSV 統計模式。

## 3. 對談、主軸與候選

正式版完整內容永遠在工作區頂部；下方為「01 對談」「02 主軸與方向」「03 候選」。桌面並列對話與工作內容，窄螢幕依序堆疊，長正式版可用鍵盤聚焦後捲動閱讀。

先說明用途、讀者、核心訊息或限制。AI 在同次回覆判斷方向是否足夠，足夠就整理待確認主軸，必要時才問一個重點。沒有固定三輪門檻，不要求填滿所有非必要資訊，也不因方向足夠而自動生成。

確認方向符合你的意思後，按「確認方向並生成候選」；這個明確操作才確認方向並呼叫一次生成。也可繼續討論，新的初次構思對話會更新待確認方向。標題名稱每次 3–5 組、短文 3 篇；長篇文章、表格、圖表每次各 1 份完整候選，全部保留，不自動指定正式版。

若 AI 明確提供單選答案，問題下方會顯示 2–6 個按鈕，可直接回答或自行輸入。按鈕名稱與完整答案不同時會同時顯示。只有最新、脈絡仍有效的問題可作答；切換來源版本、文章選段或相關脈絡後舊選項會失效。按答案不清空輸入中的草稿，選答案也不等於採用作品。

## 4. 從任何候選或正式版繼續微調

按版本上的「以此版繼續微調」，或在編輯區選「工作來源版本」。候選不必先採用；未另選來源時，AI 延續目前正式版。畫面顯示來源後，再回到對談提出具體修改。

- 標題名稱：以整組欄位為修訂單位，完整保存自訂內容。
- 短文：以完整全文為單位，不只保存變動片段。
- 長篇文章：選好來源後，勾選要改的段落或條款，沒有預設全選。AI 看見來源全文來理解上下文，只回傳所選段落；其餘原文字節、順序和既有 ID 保持不變，伺服器合併成完整新快照。沒有勾選就不呼叫修訂。

表格與圖表以完整作品為修訂單位，不用文章選段。請先選來源，再說明要改哪些欄列、節點、連線或呈現；結果保存完整結構化作品，不只保存變更片段。沒有資料時先釐清，不能用編造數字補滿統計圖。

AI 明確改寫會新增來源主版下的小版本，例如從 V2 另存 V2.1，附差異及本版目標，尚未取代正式版。可直接選新候選再改，不需先採用。若只是評價或必要釐清，就保留討論，不建立假版本。修訂既有候選或正式版不要求重走初次方向確認。

文章 AI 選段操作不能新增、刪除或改名段落，也不能修改未選範圍。若要改結構，請改用完整手動編輯區，再另存新版本。手動可改正文、段落名稱或新增／移除段落；已有段落保留 ID，新段落取得新 ID，來源不變。

已啟用類型的手動修改都可「另存新版本 V?」或以選定來源「另存小修改 V?.?」。兩者保存完整內容，不是直接覆寫。草稿尚未另存時只在目前頁面，重新整理可能遺失。

「本版目標與修改意見」合併在一欄，最多 12,000 UTF-8 bytes，從選定來源帶入。舊版不同欄位合併呈現、完全相同文字不重複，原快照不改。新保存內容是後續修訂與比較的主要依據，不被目前共用目標或舊相容欄位蓋過。

## 5. 版本樹、比較與融合

候選區按主版本分組，可展開完整內容與來源。小版本沿來源主版編號，但實際來源可能是該組任一版，請看「實際來源」；融合會列全部來源，不靠相鄰版號推測關係。正式版亦保留在歷程中，並可跳回頂部閱讀。

勾選 2–5 個不同、未封存的版本，可包含正式版與候選：

- 比較：獨立請 AI 依每版自己的目標、討論變更、修改意見與完整內容評估。目標不同會說明取捨，不按目前共同目標統一排名，也不因較新或正式版身分自動加分。比較不要求重確認目前方向，不修改版本。
- 融合：另填想保留的優點／方向，再明確按「融合所選版本為新候選」。這是另一次 AI 呼叫，保存一個新主版本、完整內容、採納／捨棄說明與來源快照。比較不會自動觸發融合，融合也不會直接變正式版。

候選可以封存及還原；正式版不能封存。封存不刪除、不釋放版本額度，也不改舊比較與引用。封存版本須先還原，才能當新的修訂、比較、融合或引用來源。

## 6. 採用、定稿、引用與匯出

明確按「設為正式版」才更換工作區頂部作品，不等於定稿。只有標題名稱採用時會依主要名稱同步更改創作項目名稱；短文／文章／表格／圖表不因此更名，所有類型都不改專案名稱或說明。生成、修訂、融合或手動另存也不更名。

項目定稿仍需有效的目前方向與正式版；已定稿或專案已結案時先重新開啟再改，舊定稿快照保留。專案結案要求所有未封存項目完成；其餘七種規劃項目不算已完成，可先封存，不能將它們假裝定稿。

可固定引用同專案另一項目的某個未封存版本。引用保存完整內容及模型來源，來源後來改版、封存或改正式版不會同步變動。要使用新來源，明確移除舊引用再加入新版。AI 不能改寫來源作品。

匯出 JSON 會包含文字、表格／圖表完整原生結構、歷史、引用、專案模型綁定與模型來源，不含 Key；分享前檢查未公開內容。作品依原瀏覽器工作階段辨識，遺失 Cookie／Session 後沒有帳號復原入口，重要內容應另存匯出。

## 7. 表格、流程圖與統計圖

### 表格

在工作區直接改欄名、表格說明及各格文字，或按新增／移除列欄。保留的列欄會沿用 ID；新增項目取得新 ID。每格只保存文字，輸入公式不會計算，也沒有 Excel 樣式、合併儲存格或外部連動。修改後明確另存主版或小版，原來源保持不變。

### 流程圖（預設）

在「流程圖文字來源（Mermaid 子集）」編輯節點及連線，通過格式驗證後顯示本程式自己的 SVG 預覽。以下只是語法範例，不代表你的實際流程：

```text
flowchart TD
Start("開始")
Draft["整理想法"]
Review{"確認方向？"}
Done("完成")
Start --> Draft
Draft --> Review
Review -->|需要調整| Draft
Review -->|確認| Done
```

- `TD` 是由上而下，`LR` 是由左至右；也接受 `graph` 標頭和 `TB`（同 TD）。新建編輯器的單一「開始」是手動佔位節點，不是 AI 已完成作品。
- 節點逐行獨立宣告：方框 `A["文字"]`、菱形 `B{"判斷"}`、圓角框 `C("開始")`。ID 以英文字母開頭，只含英數及底線，最多 40 字元，不可重複或使用 `end`、`subgraph`、`click` 等保留字。
- 連線另占一行：`A --> B` 或 `A -->|標籤| B`。端點都必須有獨立節點宣告，不能邊連線邊宣告或串接多段箭頭。可有循環與自我連線，完全相同的連線不可重複。
- 只接受受限純文字標籤；含括號或分號時必須使用上例的外層雙引號，其他特殊標記仍不接受。支援空白行、一般 `%%` 註解與單一行尾分號；不支援子圖、樣式／class、click、初始化指令、HTML、Markdown、網址、圖片或任意程式。
- 此處不是完整 Mermaid 引擎。預覽使用簡化排版，複雜連線可能重疊；長標籤在圖上可能縮略，請核對下方完整節點／連線列表和來源文字。

### 可選統計模式

明確選長條、折線或圓餅圖，來源改填真正以 Tab 分隔的 TSV：第一列是分類名稱與數列名稱，後面每列是一個分類及各數值，不是 Markdown 表格。先提供數據及用途再請 AI 整理，缺數據時應釐清；不能用範例數字當成你的真實資料。流程圖不需要提供這些統計數字。

數值只接受有限十進位字串，可有正負號、小數；不接受公式、科學記號、千位逗號、數值前後空白、NaN 或 Infinity。圓餅圖限一個非負數列且總和大於零。切換流程／統計模式時會保留原來源，不自動轉換或刪除；格式錯誤的草稿仍留在編輯器，修正後才能保存。

### 匯出與固定腳本示範

版本上的按鈕只處理那個已保存版本，不含尚未另存的草稿，也不呼叫 AI：

- 表格：CSV／TSV 只含欄名與儲存格，不含表格說明、列欄 ID、樣式或版本歷史。
- 流程圖：MMD 保留文字來源；SVG 是目前簡化排版的圖形。MMD 不含另存的圖表標題與版本紀錄，SVG 也不是可重新編輯的完整專案。
- 統計圖：TSV 保留資料來源；SVG 是圖形，不含完整共創歷史。
- 圖表可按「複製文字來源」；若瀏覽器不允許剪貼簿，改匯出 MMD／TSV 後自行複製。沒有自動匯入、同步或連線圖坊，亦未驗證相容性。

CSV／TSV 匯出會為可疑公式文字加前置單引號；統計資料中已驗證的數字保持數值，包括負數。匯出後在試算表呈現可能與原字串不同，原始文字、結構、標題／說明及完整歷史請保留專案 JSON。

「固定腳本示範（非 AI）」中，圖表可選「使用流程圖示範」，或輸入「請使用流程圖示範。」；也可明確選虛構參觀人次統計示範。節點、時段與數字全部是虛構示範，不解析或代用你提供的真實資料。對話只支援逐字替換表格說明、圖表標題或本版目標；其他內容請直接編輯另存，示範比較／融合也不是模型分析。重新整理會重設示範資料。

## 8. 容量與錯誤

全部限制以 UTF-8 位元組計，不是中文字數：標題每欄 6,000、合計 24,000；短文全文 12,000；文章 1–80 段、每段 6,000、保存全文合計 120,000。文章單次生成／融合上限 36,000；AI 修訂選段原文合計上限 24,000、回傳選段合計上限 36,000，且不得超過全文保留未選段落後的剩餘容量。手動長文保存上限不代表 AI 可一次生成同樣長度。

表格最多 12 欄、100 列，每格 2,000 bytes，欄名 120、說明 600 bytes。圖表標題 600、軸標籤各 120、來源 12,000 bytes；流程圖 1–40 個節點、0–80 條連線，節點文字 240、連線標籤 120 bytes；統計圖 1–5 個數列、1–24 列資料，標頭／分類名稱各 120 bytes、數值絕對值不超過 1 兆。表格與圖表的完整作品 JSON、文字投影各限 60,000 bytes，不能同時填滿所有欄格的單項上限。

HTTP 請求最多 1 MiB，專案資料最多 2,000,000 bytes，每項目最多 60 版（含封存）和 60 比較。超限時不截斷原文；需縮小選段、縮短本次輸入，或先匯出再建立新項目／專案。模型 output tokens 請求預算為 6,000–24,000，不是字數或成功保證。

明確格式拒收不會被當作有效結果，舊資料保留，但上游仍可能計費。逾時、斷線或寫入結果未知時先查看最新狀態，不連按重試；系統不自動重試、換模型或以腳本冒充 AI。來源與模擬檢查不等於實測，本次未完成原生 PHP、Apache／XAMPP、實機瀏覽器或真實模型驗收。

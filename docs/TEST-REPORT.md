## 本輪回覆錯誤的診斷界線

回報畫面的確切錯誤為「AI 釐清回覆不得假裝修改作品，且每次只能問一個問題。」舊驗證把 items 必須空陣列、修訂 metadata 必須空字串、總共恰一個問號及 question 最後一字必須是問號合成同一個條件。沒有當次原始模型回覆，**不能確認究竟是哪個子條件失敗**，也不能由錯誤出現在成員切換後就斷言切換失敗或某模型故障。

本輪將格式容忍與內容防護分開：有界說明 metadata 經型別／長度驗證後丟棄、不寫成新版本；評價可不追問，允許引述作品的問號、普通結尾標點及相鄰問號。仍要求真正空的 items 陣列，拒絕明顯假稱完成修改，以及引述外的多個問號群。原始 JSON 先驗證物件／陣列、必要欄位與型別，不把 items:{} 誤當 []。這不是完整自然語言理解，也不代表所有真實模型都已修好。

API error.operationOutcome 區分明確 rejected 與 unknown。已驗證拒收表示沒有保存有效結果，**不保證服務未計費**；斷線、逾時、一般內部錯誤或已嘗試而結果無法確認的請求仍先查最新狀態。不自動重試或 fallback。前端來源／DOM／傳輸測試與未執行的 PHP fixture 是不同層級，不能相互替代。

## 已確認並修正的問題

- 「選了 2 個版本仍無法比較」：介面曾把比較與目前共用目標核准綁在一起，按鈕被停用。現在比較使用各個選取版本自己的目標與修改紀錄，不要求重新核准共同目標。選取數、唯讀、封存、設定、字數限制均顯示原因；請求錯誤在畫面顯示。
- 比較請求只允許選定 ID，輸出必須完整涵蓋 2–5 版，不能重複或捏造版本；不指定唯一贏家，也不改正式版。
- 新的完整創作內容與目標／意見可能超過舊 32 KiB body 限制，已調整至有界 256 KiB，逐欄上限仍保留。
- 新 AI 設定保存／切換檢查代次，拒絕舊分頁覆寫；清除選擇是明確 null，不自動換成另一位；舊相容設定先驗證完整名單再寫入。
- 「04 選擇與微調／編輯創作內容」只保留「本版目標與修改意見」單一輸入框，以 goalAndRationale 保存，最多 12,000 UTF-8 bytes。舊分欄的不同既有文字完整帶入，僅去除完全相同的重複文字與空值；舊快照不變，重複編輯／另存不疊加標籤。修訂／比較優先以合併文字為準，相容分欄不覆蓋新方向。
- 修訂與候選由原本同一次回覆取得 goalText／changeSummary／rationale，再組成合併文字，沒有多一次摘要呼叫。舊版缺資料保持缺漏。
- 明確 promote 才以採用版本的主要名稱更新 creative item title，並記錄前後名稱；左側項目卡片與目前項目標示同步。專案名稱／說明與完整作品不變，單純生成、另存或待採用修訂不更名。
- 預設介面、示範及提示詞改為一般創作者語境；成員選單位於「和 AI 慢慢聊」面板內、標題後及討論紀錄／輸入欄之前，DOM 回歸檢查單一選單、標籤關聯、切換與取消後不重複，列印仍隱藏。舊使用者自訂文字、歷史角色與作品不改寫；模型投影的舊 student 角色轉為 user，不回存覆寫歷史。
